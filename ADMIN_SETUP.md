# Настройка административного доступа YŌRI

CRM не поддерживает публичную регистрацию. Первый владелец создаётся только отдельной серверной командой после применения миграций.

## Переменные окружения

```dotenv
NEXT_PUBLIC_APP_URL=https://your-app.example
AUTH_SECRET=
AUTH_BASE_URL=https://your-app.example
ADMIN_INITIAL_EMAIL=
ADMIN_INITIAL_PASSWORD=
ADMIN_INITIAL_NAME=Владелец YŌRI
```

- `AUTH_SECRET` — случайный секрет длиной не менее 32 символов; он не должен иметь префикс `NEXT_PUBLIC_`.
- `AUTH_BASE_URL` — точный origin CRM без завершающего пути; приватная runtime-переменная, обычно совпадающая с `NEXT_PUBLIC_APP_URL`.
- `ADMIN_INITIAL_PASSWORD` — пароль длиной 12–128 символов. Не отправляйте его в чат, логи или систему контроля версий.
- `DIRECT_URL` и `DATABASE_URL` должны относиться к одной БД и окружению.

## Создание владельца

```bash
npm run db:migrate:deploy
npm run admin:create
```

Команда идемпотентна для указанного email: повторный запуск обновляет имя, возвращает роль `OWNER`, заменяет пароль и отзывает существующие административные сессии. После успешного запуска удалите `ADMIN_INITIAL_PASSWORD` из постоянной конфигурации окружения, если повторное создание не планируется.

## Граница безопасности

- вход расположен по адресу `/admin/login`;
- signup Better Auth выключен, публичной формы регистрации нет;
- email не раскрывается через разные сообщения об ошибке;
- вход ограничен пятью попытками за 15 минут для одного источника и хранит счётчик в PostgreSQL;
- пароль хешируется встроенным адаптивным Scrypt Better Auth;
- административная сессия хранится в БД не более восьми часов;
- cookie имеет `HttpOnly`, `SameSite=Lax` и `Secure` в production;
- `proxy.ts` выполняет только ранний redirect, а защищённый layout и будущие серверные операции повторно проверяют сессию, активность и роль на сервере;
- административные ответы не кэшируются публично, а маршруты помечены `noindex`.

При отключении администратора установите `AdminUser.isActive = false` доверенной серверной операцией и удалите его активные `AdminSession`. Управление администраторами через CRM не входит в часть 5.1.
