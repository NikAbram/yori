# YŌRI

Telegram Mini App доставки суши и роллов. Текущий статус: этап 2 и части 3.1–3.2 завершены; Prisma 7 подключена к Neon, начальная миграция применена, а клиентский каталог читает 8 категорий и 25 товаров из БД через кэшируемый серверный сервис.

Для UI-QA используются Playwright и `@axe-core/playwright`: проверяются основные маршруты, клавиатурная навигация, WCAG A/AA, состояния интерфейса, изображения, горизонтальный скролл и перекрытия фиксированной навигацией.

## Neon и Prisma

1. Скопируйте `.env.example` в локальный `.env` и не добавляйте его в Git.
2. Укажите в `DATABASE_URL` pooled connection string Neon для runtime.
3. Укажите в `DIRECT_URL` direct connection string той же БД и branch для Prisma CLI и миграций.
4. Примените уже созданные миграции командой `npm run db:migrate:deploy`.
5. Заполните каталог командой `npm run db:seed`; повторный запуск обновляет те же категории и товары по уникальным slug, не создавая дублей.

`prisma migrate dev` не выполняется при запуске приложения и не предназначен для production. Без настоящего `DIRECT_URL` конфигурация использует только неразрешимый адрес домена `.invalid`, чтобы локальные schema-only команды работали, но миграция не могла случайно обратиться к чужой БД.

Основной runtime-клиент использует транзакционный `@prisma/adapter-pg` с pooled URL. Seed и простая read-only диагностика используют HTTP-адаптер Neon; операции создания заказов через него выполнять нельзя, поскольку HTTP-режим не поддерживает транзакции.

Публичный каталог выбирает только опубликованные записи и необходимые клиенту поля. Его серверный кэш помечен единым тегом `catalog`, который будет инвалидироваться после будущих изменений через CRM.

Серверные заказы, Telegram-аутентификация и CRM ещё не реализованы. UI-интеграция Telegram не является авторизацией и не использует `initDataUnsafe`: приём заказов закрыт, личные данные не показываются, а checkout пока проверяет ввод только локально и ничего не отправляет.
