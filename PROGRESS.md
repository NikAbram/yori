## Подтверждённые проверки

### Часть 3.1 — 20.10.2026

- валидная Prisma-схема и успешная генерация Prisma Client;
- применённая начальная миграция и актуальное состояние схемы Neon;
- read-only запросы через HTTP- и транзакционный Prisma Client;
- 8 категорий, 25 товаров и отсутствие дублей после повторного seed;
- успешные `lint`, `typecheck`, 15 unit-тестов и production build;
- отсутствие известных production-уязвимостей по `npm audit --omit=dev`.

### Часть 3.2 — 20.10.2026

- результат части подтверждён пользователем;
- публичные категории и товары читаются через серверный сервис `catalog` из Neon;
- неопубликованные товары и категории исключаются на уровне Prisma-запросов;
- в клиентские компоненты передаются только публичные поля;
- настроены часовой cache profile и единый тег инвалидации каталога;
- главная, каталог, карточка товара, корзина и checkout используют данные БД;
- успешно выполнены `lint`, `typecheck`, 18 unit-тестов, production build и 14 Playwright-тестов;
- Playwright подтвердил поиск, фильтрацию, карточку товара, корзину, состояния интерфейса, WCAG и целевые viewport без runtime errors.

### Часть 3.3 — 20.10.2026

- результат части подтверждён пользователем;
- сервер проверяет сырой Telegram `initData` по HMAC-SHA-256, ограничивает возраст `auth_date` и допустимое отклонение времени;
- подпись сравнивается в постоянное время, повторяющиеся параметры и подменённые, неверные, просроченные либо будущие данные отклоняются;
- Telegram ID извлекается без потери точности, а `initDataUnsafe` не используется как источник авторизации;
- сервер создаёт непрозрачную пользовательскую сессию, хранит только SHA-256 хеш токена и выдаёт `HttpOnly`, `SameSite=Lax`, `Secure` в production cookie;
- endpoint ограничивает размер и тип тела, требует same-origin запрос и возвращает приватные ответы без кэширования;
- успешно выполнены `lint`, `typecheck`, 35 unit-тестов, production build и 14 Playwright-тестов;
- реальный smoke-тест внутри Telegram остаётся на этап развёртывания с настроенным ботом и production URL.

### Часть 3.4 — 20.10.2026

- результат части подтверждён пользователем;
- серверная Zod-схема принимает только данные получателя, адрес, способ оплаты, idempotency key, ID товаров и количество; клиентские цены и итоги отклоняются;
- сервис `cart-pricing` непосредственно перед записью читает опубликованные товары и настройки из БД, проверяет наличие и рассчитывает суммы целыми копейками;
- заказ, snapshot позиций и начальная история статуса создаются атомарно в транзакции `Serializable` с повтором конфликтов;
- уникальный idempotency key безопасно возвращает исходный заказ при повторном запросе и не раскрывает заказ другого пользователя;
- checkout ограничен по числу позиций, количеству товаров, размеру тела и частоте запросов через PostgreSQL без Redis;
- `POST /api/orders` требует подтверждённую Telegram-сессию, same-origin запрос и до части 3.5 остаётся закрытым для пользователей без серверного разрешения private test;
- отдельной миграцией добавлены выключенные по умолчанию флаги способов оплаты; миграция применена к Neon и проверена через pooled и транзакционный Prisma Client;
- успешно выполнены `prisma generate`, `prisma validate`, `prisma migrate deploy`, read-only DB checks, `lint`, `typecheck`, 53 unit/integration-теста, production build и 14 Playwright-тестов;
- клиентская отправка заказа остаётся выключенной до завершения политики `private_test` и allowlist в части 3.5.
